# 从零到微信小游戏发布

本手册区分「代码完成」「微信体验版」「审核通过」「正式发布」。当前代码能生成小游戏包，但没有 AppID；浏览器可运行不代表已经上线微信。

## 1. 先理解需要什么

- 微信小游戏账号：用于管理游戏，不等同于普通个人微信号，也不要误注册为只有小程序能力的项目。
- 主体：账号归属的个人或组织。你是否能以该主体发布所选游戏类目，取决于官方当前准入政策与资质要求。
- AppID：游戏的公开标识，可以填到本地构建配置；不是 AppSecret。
- 开发者工具：电脑上的微信官方软件，用来导入代码、调试、真机预览和上传版本。
- 平台审核：上传后仍需提交审核，通过后才具备正式发布条件。

官方入口：微信公众平台 <https://mp.weixin.qq.com/>；小游戏文档 <https://developers.weixin.qq.com/minigame/dev/guide/>；开发者工具下载 <https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html>。本环境未核实当前后台页面及准入条款；如名称发生变化，以官方页面为准，不向第三方代办提供密钥。

## 2. 注册与资格核实（用户操作）

1. 在公众平台注册入口查看「小游戏」相关注册流程；按官方要求准备邮箱、管理员微信、主体信息。
2. 先确认个人/组织是否支持计划中的游戏类目、是否需要认证、备案或其他游戏运营资质，再决定主体；不要因为开发示例可运行就假设可上线。
3. 按实际情况完成管理员验证、主体资料及相关手续。不确定时可将不含身份证、手机号和密钥的错误文字提供给开发者协助分析。
4. 进入账号后台找到开发设置中的 AppID，确认自己是管理员或已被添加为开发者。
5. 不要把 AppSecret、上传私钥、身份证、验证码提交到仓库或聊天。首版不需要 AppSecret，也不需要为了开发同屏玩法购买服务器。

若注册或资质不满足，这是正式上线卡点。可先继续浏览器测试与开发工具允许的测试功能，但不得声称公开发布成功。

## 3. 在电脑运行代码

安装 Node.js 22 或更新版本、Git、微信开发者工具。从 GitHub 获取本分支或合并后的 main，在仓库目录运行：

```bash
npm run check
npm test
npm run build
```

没有第三方 npm 依赖，无需 npm install。`dist/web` 是浏览器版本；`dist/wechat` 是微信小游戏项目。默认 `touristappid` 仅为占位符，不保证开发工具允许游客小游戏预览，不能用于上传。

浏览器本地体验：执行 `npm run dev`，在本机打开终端提示端口对应的地址；仅用于开发验证，不是微信正式入口。

取得 AppID 后，在 macOS/Linux 终端执行：

```bash
WX_APPID=你的小游戏AppID npm run build
```

Windows PowerShell：

```powershell
$env:WX_APPID="你的小游戏AppID"
npm run build
```

只修改生成的项目配置，不把凭证写入源码。每次重新构建都需要同样设置 AppID；生成目录不入 Git。

## 4. 导入与真机预览

1. 打开微信开发者工具，使用管理员/开发者微信扫码登录。
2. 选择小游戏项目导入，将目录指向仓库里的 `dist/wechat`，核对 AppID 与后台账号一致。
3. 编译并检查控制台错误；测试大厅 → 开局 → 落子 → 结算 → 再战 → 战绩。
4. 点击预览，用手机扫码；如被提示无权限，在后台添加相应体验成员，不关闭安全校验绕过问题。
5. 更改源码后先重新构建，再在开发工具重新编译。不要只修改 dist 后忘记同步源码。

## 5. 必须完成的验收

- [ ] 微信开发工具编译无阻断错误。
- [ ] iOS 与 Android 各一台真机完成胜局、平局及再战。
- [ ] 玩家 X/O、轮流提示、获胜连线、个人步数含义清晰。
- [ ] 重复点击已占用格、同时多指点击不造成非法回合。
- [ ] 退出/重开确认，取消后棋盘不变。
- [ ] 切到后台再回来棋盘正常；完全重启后已完成战绩仍在。
- [ ] 小屏、刘海屏、底部手势区可操作，无裁切或遮挡。
- [ ] 存储异常不会阻塞游戏；无登录、云同步或联机能力的误导描述。
- [ ] 核对实际包体、基础库版本要求与性能表现，并填入 VALIDATION.md。

本项目尚未在微信开发工具或真实手机上执行这些检查，不能预先勾选。

## 6. 上传、审核、发布（用户操作）

1. 完成上述验收，记录 Git 提交号与版本，例如 `0.1.0`。
2. 在开发工具点击上传，版本描述填写「双人同屏井字棋、大厅和本机战绩」。
3. 在官方后台版本管理查看上传版本，按平台支持的方式设为体验版，邀请少量体验者完成回归。
4. 准备名称、原创图标、说明、截图、类目、隐私指引、客服/联系渠道，以及后台列出的备案/资质材料。不能将「不联网」视为免除所有合规要求；确认存储 API 的申报要求与未成年人保护要求。
5. 提交审核，按驳回原因修正对应内容再提交；不要虚报功能、资质或用户数据用途。
6. 审核通过后，由管理员在平台执行正式发布。该操作会影响真实用户，应基于具体版本验收后决定。
7. 用普通体验者账号从微信实际入口启动线上版，确认版本、大厅、游戏、战绩以及重启恢复。

## 7. 发布异常与回退

保留每次上传的版本号、提交号、检查结果、发布时间和平台审核结果。若线上有严重问题，停止推广；在后台确认是否支持回退至已审核版本，按当前能力操作。没有可回退版本时修复并重新审核，不承诺即时回滚。CI 构建产物不能替代微信上传、审核及发布。

## 8. 联机上线前额外准备

只有 P1 开发时再开通云资源，先确认账号支持与预算。设置最低权限、数据库规则、用量告警、测试/生产隔离、服务端密钥管理，并完成断线与防作弊验收。P0 本机记录不会自动成为云端用户战绩。
